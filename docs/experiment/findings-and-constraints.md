# 四个问题、根因和四条约束

这里区分真实运行缺陷与静态维护性风险。接受的问题为 2 项中等、2 项低风险；没有把未经证明的部分提交或假的成功审计写成已发生缺陷。

| 问题 | 观察及根因 | 约束与修改 | 验证和剩余边界 |
| --- | --- | --- | --- |
| 登录别名 | 甲邮箱=乙用户名，两个不同合法密码都不能登录。逐列唯一被误解为入口唯一。 | 校验每个不同候选，最多两身份；固定两次 BCrypt（必要时占位），恰好一个匹配才选择身份，再检查启用状态。保持原输入域、唯一键和 401 语义。 | 原登录场景通过，补充七个身份边界变体通过。同别名、同有效密码对应双身份仍 401，不能任选其一。 |
| 协议异常 | 有认证和有效 CSRF 时，不支持方法和媒体类型返回 500；异常白名单遗漏了两类客户端协议错误。 | 显式映射到既有 INVALID_INPUT/400，保留真实 500、401、403、409 和脱敏字段。 | 同一协议探针由 500 变为 400；不能解释为所有 HTTP 问题均已检查。 |
| 标签 N+1 | 1/20 行页分别执行 1/20 次标签 SELECT。单条详情内部 SQL 被逐行用于集合。 | 非空页一次批量读取全部标签，按原行顺序分组组装；不改分页、总数、排序或 DTO。 | MySQL 实际计数变为 1/1，内容及分页语义保持；不是生产时延 benchmark。 |
| 失败观察与可读性 | 六个 facade 复制失败审计模板，关键 apply 步骤挤在很长的单行中。当前没有部分提交或假的 SUCCESS 的运行证据。 | 共用 audit owner 的窄观察契约，不包围业务事务；独立失败审计、原异常和已提交清理特例保留；apply 仍同事务且步骤可读。 | 静态调用路径复查、审计及四处故障回归；不把风险降低冒称为修复已发生数据损坏。 |

四条约束与四个根因一一对应。第二版继续使用同一 64 FR、97 BR、13 实体/151 字段/34 FK、两套状态机、原 API 和 SQL 定义。没有删掉第一版失败或改业务预期。

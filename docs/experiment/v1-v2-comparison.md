# 两次实现的同口径比较

应用 V1/V2 是代码迭代，不是需求自身的正式内容版本号。比较建立在固定第一版以后进行独立检查、接受根因、生成四条约束，再按相同场景运行第二版的实际过程上。

| 项目 | 应用 V1 | 应用 V2 |
| --- | --- | --- |
| 实际执行原代表 ID | 32 | 相同 32 |
| PASS / FAIL / BLOCKED | 31 / 1 / 0 | 32 / 0 / 0 |
| 原 103 项中 NOT_RUN | 71 | 71 |
| 四个真实问题 | 两个功能/协议问题，查询和维护性风险 | 四个选定范围有界改进；剩余身份歧义继续披露 |
| 分页 1/20 行标签 SELECT | 1 / 20 | 1 / 1 |
| 后端开发检查 | 45 | 72（新增定向 27） |
| 前端开发检查 | 152 | 152 |

同一场景预期和运行脚本没有为 V2 放宽。协议、认证边界和查询计数单独补充，不增加原代表 ID 数量。两条真实浏览器旅程覆盖首次批准、退回重审、变更评审、应用新版本与重新验证，以及拒绝、重开和取消分支。

第一版失败定位为登录身份选择中的假设，不是功能流程全部不可用。维护性问题没有证据表明第一版会部分提交；不能把四项全部说成安全漏洞。第二版四处故障仍完整回滚，已执行的权限、审计、重复和并发场景保持原预期。

未运行 71 项、部分未覆盖变体、同别名同有效密码双身份仍 401、未开展生产安全与负载认证，均是结论边界。当前展示截图来自独立数据，不代替历史运行证据。

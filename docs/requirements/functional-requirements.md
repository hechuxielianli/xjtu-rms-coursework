# 完整功能需求

64 条原业务语义，按原编号列出；单项目范围，不含项目排期和完整测试管理。

| 编号 | 功能 | 内容 |
| --- | --- | --- |
| FR-AUTH-001 | 用户登录 | 合法且启用的用户可以使用用户名或邮箱及密码建立登录会话。 |
| FR-AUTH-002 | 用户退出登录 | 用户退出登录后，服务端会话立即失效。 |
| FR-AUTH-003 | 身份认证 | 访问受保护资源时，系统验证会话、账号启用状态和实际角色，不接受客户端声明的身份。 |
| FR-USER-001 | 创建用户 | Administrator 创建用户时提供 username、email、displayName、initialPassword 和至少一个预定义角色 roles；用户名和邮箱唯一。initialPassword 仅作请求输入，服务端用 BCrypt 生成非空 passwordHash；数据库及接口不保存明文密码，passwordHash 永远不返回客户端。 |
| FR-USER-002 | 修改用户 | 管理员修改用户的邮箱、显示名称等基本资料，保留内部标识和历史引用。 |
| FR-USER-003 | 启用或禁用用户 | 管理员启用或禁用用户；禁用后拒绝登录及受保护操作。 |
| FR-USER-004 | 查看用户 | 管理员查询用户列表和资料；密码哈希不返回客户端。 |
| FR-USER-005 | 分配角色 | 管理员为用户授予或撤销预定义角色，启用用户至少保留一个角色。 |
| FR-USER-006 | 权限控制 | 服务端按用户角色并集检查操作权限，并独立执行自我评审排除等业务限制。 |
| FR-REQ-001 | 创建需求 | 需求工程师创建需求；系统生成唯一稳定编号，记录正式内容和创建信息，初始状态为 DRAFT。 |
| FR-REQ-002 | 查看需求详情 | 所有授权用户查看需求详情，包含当前内容、生命周期、管理信息及追踪入口。 |
| FR-REQ-003 | 修改草稿需求 | 需求工程师直接编辑 DRAFT 的八项正式内容；其他状态禁止直接编辑。 |
| FR-REQ-004 | 撤销草稿需求 | 需求工程师仅可逻辑撤销从未提交评审且没有有效关联的 DRAFT；保留原记录及审计。 |
| FR-REQ-005 | 设置需求层级与性质 | 需求工程师分别设置需求层级 BUSINESS/USER/SYSTEM 与性质 FUNCTIONAL/QUALITY/CONSTRAINT。 |
| FR-REQ-006 | 设置需求优先级 | 需求工程师设置 LOW/MEDIUM/HIGH/CRITICAL 优先级；已形成基线后经正式变更修改。 |
| FR-REQ-007 | 管理需求标签 | 需求工程师创建或复用标签、添加或移除需求标签，审计变化且不产生正式版本。 |
| FR-REQ-008 | 指定需求负责人 | 需求工程师指定或清除负责人；新指定者须启用，变化被审计且不产生正式版本。 |
| FR-LIFE-001 | 维护需求状态 | 系统维护需求当前生命周期状态，并保留每次状态变化的操作人、时间及版本上下文。 |
| FR-LIFE-002 | 提交需求评审 | 需求工程师提交完整的 DRAFT 需求，创建新的评审快照并将需求置为 UNDER_REVIEW。 |
| FR-LIFE-003 | 控制状态迁移 | 系统仅通过规定的业务动作执行合法状态迁移，拒绝客户端任意指定状态。 |
| FR-LIFE-004 | 标记需求已实现 | 项目成员将 APPROVED 的当前正式需求标记为 IMPLEMENTED，并记录实现说明。 |
| FR-LIFE-005 | 标记需求已验证 | 项目成员将 IMPLEMENTED 的当前正式需求标记为 VERIFIED，并记录验证说明。 |
| FR-LIFE-006 | 重新打开被拒绝需求 | 需求工程师将 REJECTED 重新打开为 DRAFT，保留既有评审记录和首次提交时间。 |
| FR-REV-001 | 查看待评审需求 | 评审者查询待处理需求及其 PENDING 评审轮次，查看该轮不可变提交快照。 |
| FR-REV-002 | 批准需求 | 非创建者的评审者批准待处理需求，完成该轮评审并原子创建 V1。 |
| FR-REV-003 | 拒绝需求 | 非创建者的评审者填写拒绝理由，完成该轮评审并将需求置为 REJECTED。 |
| FR-REV-004 | 要求修改需求 | 非创建者的评审者填写修改意见，完成该轮评审并将需求退回 DRAFT。 |
| FR-REV-005 | 填写评审意见 | 评审决策保存意见；REJECT 和 REQUEST_CHANGES 的意见必须非空。 |
| FR-REV-006 | 保存评审历史 | 每次提交保留八项完整内容快照；已完成轮次保留决策、评审者、意见及时间且不可覆盖。 |
| FR-VER-001 | 创建正式版本 | 首次批准产生 V1；后续仅通过应用批准变更产生连续编号的正式版本，保存完整内容及产生来源。 |
| FR-VER-002 | 查看版本历史 | 授权用户查看需求全部正式版本的列表、时间和产生原因。 |
| FR-VER-003 | 查看指定版本 | 授权用户查看指定历史版本的八项完整内容，历史版本不可编辑。 |
| FR-VER-004 | 查看版本变更原因 | 授权用户查看版本产生者、时间、原因及批准评审或变更来源。 |
| FR-VER-005 | 标识当前版本 | 系统明确标识当前正式版本；首次批准前为空，形成基线后指向本需求最新版本。 |
| FR-REL-001 | 创建需求关系 | 需求工程师在两个存在且未撤销的不同需求之间建立语义关系。 |
| FR-REL-002 | 删除需求关系 | 需求工程师解除已有关系，保留解除前值的审计且不删除两端需求。 |
| FR-REL-003 | 设置关系类型 | 支持 DEPENDS_ON、REFINES、DERIVED_FROM、CONFLICTS_WITH、DUPLICATES、RELATES_TO，并执行方向和对称去重规则。 |
| FR-REL-004 | 查看关联需求 | 授权用户查看需求的入向和出向直接关系以及对端需求。 |
| FR-REL-005 | 防止需求自关联 | 系统拒绝需求自关联、重复关系及 DEPENDS_ON 依赖环。 |
| FR-REL-006 | 关系追踪 | 授权用户在当前关系图中沿关联需求进行追踪；遍历去重并显示方向与类型。 |
| FR-CR-001 | 创建变更请求 | 需求工程师针对 APPROVED、IMPLEMENTED 或 VERIFIED 的需求创建变更，由服务端复制当前正式版本及内容。 |
| FR-CR-002 | 描述变更内容 | 变更草稿保存申请标题、理由、基准版本和八项完整建议内容，仅 DRAFT 可编辑。 |
| FR-CR-003 | 提交变更评审 | 需求工程师提交完整变更，创建新的评审快照并将变更置为 UNDER_REVIEW。 |
| FR-CR-004 | 批准变更请求 | 非提出者的评审者批准待处理变更，完成该轮评审并置为 APPROVED；此时不创建新版本。 |
| FR-CR-005 | 拒绝变更请求 | 非提出者的评审者填写拒绝理由，完成该轮评审并将变更置为 REJECTED 终态。 |
| FR-CR-006 | 执行批准变更 | 需求工程师应用 APPROVED 且基准仍为当前版本的变更，在同一事务中创建新版本、更新需求、完成变更及审计。 |
| FR-CR-007 | 保存变更历史 | 系统保留变更及每轮评审的基准、申请理由、建议内容快照、决策和产生版本的关联。 |
| FR-CR-008 | 取消草稿变更请求 | 变更提出者可取消自己的 DRAFT，置为 CANCELLED 终态并释放活动占用。 |
| FR-CR-009 | 要求修改变更请求 | 非提出者的评审者填写修改意见并将变更退回 DRAFT；保留旧轮次，重提时创建新轮次。 |
| FR-COM-001 | 创建评论 | 需求工程师、评审者和项目成员对未撤销需求发表评论，正文非空。 |
| FR-COM-002 | 查看评论 | 所有授权用户查看需求评论；已逻辑删除评论显示删除标记，不返回正文。 |
| FR-COM-003 | 标识评论作者 | 评论作者和时间由认证上下文与服务端生成，发布后不可改变。 |
| FR-COM-004 | 逻辑删除本人评论 | 评论作者仅可逻辑删除本人评论；保留正文、作者、创建及删除信息，不改变需求版本。 |
| FR-SEARCH-001 | 查看需求列表 | 所有授权用户分页浏览未撤销需求列表。 |
| FR-SEARCH-002 | 关键词搜索 | 用户按照稳定编号、标题或描述关键词搜索需求。 |
| FR-SEARCH-003 | 按状态筛选 | 用户按当前生命周期状态筛选需求。 |
| FR-SEARCH-004 | 按需求性质与层级筛选 | 用户分别按需求性质和层级筛选需求。 |
| FR-SEARCH-005 | 按优先级筛选 | 用户按优先级筛选需求。 |
| FR-SEARCH-006 | 按标签筛选 | 用户按标签筛选需求，组合条件采用 AND 语义。 |
| FR-SEARCH-007 | 综合查看需求追踪信息 | 用户从需求详情访问当前关系、正式版本、两类评审、变更、评论及业务审计。 |
| FR-AUDIT-001 | 记录关键操作 | 关键业务操作记录可信操作人、目标、操作、时间和结果；审计不保存密码或会话凭证。 |
| FR-AUDIT-002 | 记录状态变化 | 需求和变更的合法状态迁移保存前后状态及版本上下文。 |
| FR-AUDIT-003 | 记录版本变化 | 版本产生保存前后版本和批准/变更来源，与业务操作在同一事务提交。 |
| FR-AUDIT-004 | 查看需求历史 | 所有授权用户查看所查需求的业务历史；仅管理员访问全系统审计，不提供审计修改接口。 |
